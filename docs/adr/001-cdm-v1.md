# ADR-001: The common data model, version 1

- **Status:** Accepted (drafted 2026-09-02; accepted by the user 2026-09-02)
- **Date:** 2026-09-02
- **Plan reference:** [architecture.md](../architecture.md) section 2; questions 7–14, 36
- **Implemented by:** `proto/altavista/v1/*.proto`, `crates/av-cdm` (P0)
- **Depends on:** [ADR-000](000-scope-and-lineage.md); spoore ADR-000 (the Gaussian rule), spoore ADR-004 (event time, total order)

## Context

spoore's CDM (`spoore.v0`) declares state spaces, carries Gaussian states with an event-time
epoch, labeled Gaussian-mixture beliefs, and measurements with provenance. It was built for
an estimator in Earth-local frames (ECEF, ENU, NED, body) over Unix nanoseconds. It has no
design-time products, no identity that survives from a design into a track, no heavy
payloads, no handling labels, and no commands.

AltaVista must carry an entity from a design reference mission through feasibility runs,
software-in-the-loop, and live execution, across space, air and ground, with RPO and OSAM
requiring relative frames and centimetre-scale precision, under CMMC handling rules. The
representation must therefore say, for every quantity, which frame, which time scale,
which units, which entity, which label, and who authored it, and it must stay
backward-compatible from the first release because plugins and DRMs written by others will
depend on it (question 14).

## Decision

### Time

**Epochs are `int64` nanoseconds on TAI** (question 7). The field keeps spoore's name and
number (`epoch_ns`, field 4 of `GaussianState` and `Measurement`) so the wire shape is
unchanged; the *scale* is declared TAI by this ADR. Boundary conversions (UTC, TT, TDB, GPS,
UT1) go through `EpochIn { ns, scale }` and one versioned leap-second table shipped with the
platform and checked against GMAT's LSK file in CI (question 8). GMAT's A1 scale is TAI plus
0.034 381 7 s and is converted inside the GMAT adapter only.

Event time only, never arrival time, and `(epoch, message_id)` as the total order, exactly
as spoore ADR-004.

### Units

**SI internally** (question 9): metres, metres per second, radians, seconds, kilograms.
Kilometres exist only inside the GMAT adapter, and the parity goldens (ADR-002) cover that
conversion.

### Frames

**A frame is a registry entry, not an enum** (question 10). `FrameDefinition` declares an
`id`, an origin that is a **body, a platform, or an entity**, an axes kind, and for local
frames a geodetic origin. Day-one axes kinds: `ICRF`, `MJ2000_EQ`, `MJ2000_EC`, `BODY_FIXED`
(ITRF for Earth), `ENU`, `NED`, `PLATFORM_BODY`, and the entity-relative **`RIC`, `VNB`,
`LVLH`** that RPO and OSAM need. A state space references a frame by id; a measurement
carries `frame_id` (a new string field 9; spoore's enum field 7 is reserved and converted).
GMAT's `CoordinateSystem` is the reference implementation and the validator: every frame
definition names its GMAT realization (`ObjectReferenced` axes for the relative kinds), and
the frame service refuses a definition GMAT cannot build.

### Belief

**spoore's rule stands** (question 12): continuous state is Gaussian, discrete belief is a
calibrated categorical, joint belief is a labeled mixture. `GaussianState`, `MixtureComponent`,
`Belief` and `Innovation` keep spoore's shapes and field numbers.

### New first-class messages

- **`Entity`**: the identity that survives from design to execution. The DRM's entity id is
  authoritative; an asset catalog maps external identifiers (NORAD, tail number, MAVLink
  sysid, CCSDS APID) to it as `Alias { scheme, value }`; tracks bind to entities through
  association evidence, never by assumption (question 13).
- **`Trajectory`**: a design-time product. Samples of mean and, when the DRM asks for it,
  covariance from the state transition matrix; an interpolation contract (Hermite with
  velocity); segments naming the propagator and force-model hash; events (question 11).
- **`Event`**: maneuver, contact, eclipse, lifecycle, command transition, fault, custom.
  Typed, epoch-stamped, with provenance.
- **`AssetRef`**: a reference to a heavy payload (object-store URI, SHA-256, size, media
  type, spatial and temporal extent, label). Messages carry references, never payloads.
- **`Envelope`, `Batch`, `SignedBatch`**: every message carries a handling label, its
  producer and a batch id; the edge signs batches (ECDSA P-384) and chains batch hashes per
  producer (question 36).
- **`Provenance`**: who or what authored an artifact (human, agent, service), through which
  tool, against which configuration and dataset hashes. LLM-drafted artifacts are recorded
  the same way as hand-written ones.
- **`Command`**: the one message with authority semantics: idempotency key, class, deadline,
  a logged state machine (`PROPOSED → CHECKED → AUTHORIZED → DISPATCHED → ACKED`, with
  `REJECTED`, `EXPIRED`, `FAILED`) and explicit ack levels (question 55). ADR-007 will own its
  policy; the message shape lands now so the log schema never changes under it.
- **`SystemDefinition`, `SosConfiguration`, `DesignReferenceMission`**: the declared,
  hashed design artifacts of ADR-005, defined now because the log records their hashes from
  the first run.

### Compatibility

**Strict from P0** (question 14): `buf breaking` with the `FILE` rule set in CI; only
backward-compatible changes within `altavista.v1`; a review gate on every proto change;
`v2` is a new package, never an edit. `spoore.v0` messages convert to `altavista.v1` by a
recorded adapter in `av-cdm` (scale shift on epochs, enum-to-registry on frames, no other
semantic change).

## Alternatives considered

**Unix nanoseconds, as spoore has them.** Matches wall clocks and spoore's habit. Rejected
because UTC is not monotonic across a leap second, so a duration spanning one is wrong by a
second unless every consumer carries the table, and replay ordering by `(epoch, id)` can
invert. TAI has no discontinuities; the table is needed only at the boundary.

**GMAT's A1 Modified Julian Date as a double.** Zero conversion at the GMAT boundary.
Rejected: about a microsecond of resolution at current epochs, and spoore ADR-004's argument
that `f64` cannot carry present-day timestamps to the nanosecond applies unchanged.

**Kilometres internally.** Zero conversion for GMAT. Rejected because spoore, every non-space
domain and most sensor feeds are SI, so the conversion would move to many sites instead of
one, and a unit error is the classic silent mission-loss bug.

**Frames as an enum.** spoore's choice, and enough for Earth-local tracking. Rejected because
RPO needs frames whose origin and axes are another entity's state, which is not enumerable;
a registry validated by GMAT is the only representation that can say what `RIC` means for
*this* target at *this* epoch.

**Particles or set-valued uncertainty in the CDM.** Considered for long-horizon
conjunction and reachability. Rejected per spoore ADR-000: it relocates the commensurability
problem to every consumer. Anything non-Gaussian converts at the boundary with a recorded
approximation.

**Free-form schemas until the first external plugin.** Faster for a month. Rejected because
the DRMs authored during that month would need migration, and the evidence pattern
(ADR-004) assumes the log's schema is stable enough to audit.

## Consequences

**spoore's `epoch_ns` acquires a declared scale.** Today spoore neither states nor depends
on a scale (its scenarios are synthetic). The upstream PR documents the field as TAI and adds
the adapter; until it lands, `av-cdm` shifts on ingest and egress.

**Every frame must be registered before use, and GMAT must be able to build it.** The
frame service therefore needs a GMAT process at registration time (not at run time), which
is where the GMAT dependency of ADR-002's depth 2 is unavoidable.

**Message envelopes cost bytes.** A label, a producer id and a batch id on every message
is roughly 40–80 bytes; at spoore's rates (thousands of measurements per second) it is
noise, and the alternative (labels inferred from topic) fails the moment two labels share
a topic.

**Commands and design artifacts are in the CDM before their services exist.** This is
deliberate: the log's schema is the platform's memory, and adding a message later is
cheap, but changing one is a `v2`.

**Provenance is mandatory on artifacts, optional on measurements.** A measurement's
provenance is its envelope; an artifact's is who made it and from what, and an artifact
without provenance is rejected by the catalog.

## What would falsify this

The premise is that one message set can serve estimation, design, simulation and command
without a breaking change in its first major version.

The observables: a `buf breaking` failure that the review gate cannot avoid by adding a
field; a frame a DRM needs that the registry cannot express (an axes kind beyond the ten
declared, or an origin that is neither body, platform nor entity); or a domain whose
uncertainty cannot be reduced to a mixture at the boundary without a monitor flagging it
(spoore's NEES/Mardia pair). Any of those is a `v2` conversation, and this ADR names the
day it should happen rather than letting the schema drift.

## Amendment 2026-09-03: `AXES_KIND_LVLH` renamed `AXES_KIND_VVLH`

Team 1's M11.3 pinned burns against GMAT's own `ImpulsiveBurn` and measured that GMAT's
`Axes = LVLH` is X = R, Y = N×R, Z = N, which is this platform's `AXES_KIND_RIC`, while the
convention this ADR ratified under the name LVLH (question 73: Z = −R toward nadir, Y = −N,
X = N×R) is what the rendezvous literature usually calls VVLH. The same 20 m/s burn authored
under the two readings of "LVLH" differs by 28.284 m/s at the burn and 276 km one hour later.
The user decided (question 106) to rename ours: `AXES_KIND_VVLH = 10` keeps the number, the
old name is `reserved` in `core.proto` so it can never be reintroduced, a DRM naming
`AXES_KIND_LVLH` is a typed load error, and authors who want GMAT's LVLH burn axes use
`AXES_KIND_RIC`. The convention itself is unchanged. The two lines above that say "LVLH"
(the frame list in the Decision and the GMAT reference) are to be read as VVLH; the GMAT
reference's own `LVLH` realization is RIC. gmatviz's `Scenario.maneuver(frame="LVLH")`
emits GMAT's literal axes and documents that equivalence; `frame="VVLH"` realizes ours
through an ObjectReferenced system.
