# av-cdm

AltaVista Common Data Model v1 (`altavista.v1`, [ADR-001](../../docs/adr/001-cdm-v1.md)):
generated wire types, TAI epoch handling with a versioned leap-second table, SI/GMAT unit
conversions, and the `spoore.v0` compatibility adapter.

## Module layout

- **`pb`** -- generated `altavista.v1` message and enum types, compiled from
  `proto/altavista/v1/*.proto` by `build.rs` via `prost-build`. `envelope.proto`'s
  `google.protobuf.Any` is mapped onto `prost_types::Any` (`extern_path` in `build.rs`)
  rather than regenerated locally. Treated strictly as a transport encoding -- every proto
  field is optional and every `repeated double` is an unconstrained `Vec` -- exactly like
  spoore's own `proto` module.
- **`time`** -- `Tai`, a newtype over `i64` nanoseconds on the TAI scale, plus the boundary
  conversions to/from UTC (table-driven), TT (`+32.184 s`), GPS (`-19 s`), and GMAT's A.1
  atomic time (`+0.0343817 s`, exposed as an MJD float: `A1MJD = JD - 2430000.0`).
- **`units`** -- SI (metres, metres/second) <-> kilometres, the one conversion site for the
  GMAT boundary (ADR-001 "Units").
- **`spoore_v0`** -- conversions between `spoore-cdm`'s hand-written native types
  (`GaussianState`, `Belief`/`MixtureComponent`, `Measurement`, `Innovation`) and this
  crate's `pb` types: the TAI/UTC epoch shift and the `Frame` <-> `frame_id` mapping
  (ADR-001 "Compatibility", `proto/README.md`).
- **`covariance`** -- a Cholesky-based SPD hygiene check applied to a propagated covariance
  *before* it crosses into a `spoore_cdm::GaussianState` (`docs/open-questions.md` question
  80): see "Covariance hygiene" below.

## The leap-second table

`data/time/leap_seconds.json` is generated by `scripts/gen_leap_seconds.py` from GMAT's own
SPICE leap-second kernel, `GMAT R2026a/data/time/SPICELeapSecondKernel.tls` (the
`DELTET/DELTA_AT` block). It records, per whole-second step since 1972-01-01, the offset
(`tai_utc_offset_seconds`), the UTC calendar instant it takes effect
(`utc_effective`/`utc_effective_unix_ns`, proleptic: every day is 86 400 SI seconds), and
the equivalent TAI instant (`tai_effective_ns = utc_effective_unix_ns +
tai_utc_offset_seconds * 1e9`). `av_cdm::time` embeds the JSON with `include_str!` and
parses it once behind a `std::sync::OnceLock`.

Regenerate it with:

```bash
.venv/bin/python scripts/gen_leap_seconds.py \
  "GMAT R2026a/data/time/SPICELeapSecondKernel.tls" \
  data/time/leap_seconds.json
```

The generator is deterministic (no wall-clock timestamp embedded, fixed field order); a
fresh run against the unchanged kernel reproduces the committed file byte-for-byte -- this
was reverified before writing any Rust against it.

### Documented approximations (see `time.rs`'s module doc for the full derivation)

- **Before 1972-01-01T00:00:00Z**: the table has no entries. Both `to_utc_nanos` and
  `from_utc_nanos` clamp to the table's first offset (10 s) -- the same convention SPICE's
  own `deltet_` routine uses, and the one `leap_seconds.json` documents as
  `clamped_before_first_entry`. The real historical relationship (the pre-1972 "rubber
  second") is **not** modeled. **Measured**: at 1965-06-15, GMAT's `TimeSystemConverter`
  (which does implement the historical relationship) reports TAI-UTC = 3.85 s against our
  clamped 10 s, a 6.146 s deviation -- see `tests/test_leap_seconds.py`'s
  `test_pre_1972_deviation_from_gmat_is_bounded_and_recorded`, which records this rather
  than hiding it. Do not trust this crate's UTC conversions before 1972.
- **After the table's last entry** (2017-01-01T00:00:00Z, offset 37 s -- there has been no
  further leap second as of this writing): both directions extrapolate that offset forward.
  Correct only until IERS schedules another one and the table is regenerated.
- **UTC->TAI has no unique inverse across a positive leap second.** A proleptic UTC
  nanosecond count cannot represent the leap second itself (there is no `23:59:60`), so the
  last SI second before an insertion and the leap second itself collapse onto the same
  `utc_ns`. `Tai::from_utc_nanos` resolves this by always returning the *post*-insertion
  reading; the pre-insertion instant is only reachable by subtracting one second from
  `utc_ns` first. Tested in `time.rs`
  (`from_utc_nanos_resolves_the_leap_second_collision_to_the_post_insertion_reading`).

### Measured agreement with GMAT (`tests/test_leap_seconds.py`)

Twelve epochs, 1972 through 2026-09-02 ("present"), including both sides of four
leap-second boundaries, checked against `TimeSystemConverter.Convert` in GMAT's own MJD
convention:

| Check | Tolerance | Worst-case residual measured |
|---|---|---|
| TAI-UTC offset (table-covered, 1972+) | 5e-6 s | **1.518e-07 s** (~150 ns) |
| A1 <-> TAI relation (1972+) | 5e-6 s | **0.0 s** (exact) |
| Pre-1972 (documented clamp deviation) | sanity bound only | 6.146 s (expected; see above) |

The 5 microsecond tolerance is the realistic bar: GMAT's `Convert` works in double-precision
MJD days, so round-off at present-day magnitudes (~60 000 days) puts the theoretical floor
around a microsecond, while a whole-second or sign error would show up six orders of
magnitude larger.

## Frame mapping (`spoore_v0::frame`)

`spoore.v0`'s `Frame` enum carries no origin (no platform id, no geodetic point);
`altavista.v1` frames are registry entries (`FrameDefinition`: id, origin, `AxesKind`,
optional geodetic origin). There is no way to recover a genuinely registrable
`FrameDefinition` from a bare `Frame` value, so the adapter maps each variant to a fixed,
well-known `frame_id` string instead -- total and stable in both directions, but **not**
itself a registered frame (a caller needing a real one must register it and remap):

| `spoore_cdm::Frame` | v1 `frame_id` | `AxesKind` (documentation only) | origin (documentation only) |
|---|---|---|---|
| `Ecef` | `earth.ecef` | `AXES_KIND_BODY_FIXED` | body `"Earth"` |
| `Enu` | `earth.enu.generic` | `AXES_KIND_ENU` | body `"Earth"`, no geodetic point recorded |
| `Ned` | `earth.ned.generic` | `AXES_KIND_NED` | body `"Earth"`, no geodetic point recorded |
| `Body` | `platform.body.generic` | `AXES_KIND_PLATFORM_BODY` | no `reference_entity_id` recorded |
| `LocalCartesian` | `sim.local_cartesian` | `AXES_KIND_LOCAL_CARTESIAN` | none (frameless) |

An unrecognized `frame_id` decoding back to `spoore_cdm::Frame` is a typed error
(`spoore_v0::Error::UnknownFrameId`), never a silent default.

## Covariance hygiene (`covariance` module, `docs/open-questions.md` question 80)

**Why here.** A covariance produced by `av_dynamics::propagate_covariance` or
`gmat_service.model._propagate_covariance` is, at the moment it is produced, a plain `Vec<f64>`
-- neither crate constructs a `spoore_cdm::GaussianState` at all. `av-cdm` is where that
eventual crossing is meant to be validated (`spoore_v0`'s own module doc: "validation happens
here, once, at this boundary"), and it already depends on both `nalgebra` and `spoore-cdm`
(see `Cargo.toml`), so this check lives here rather than in `av-dynamics` (deliberately kept
free of any dependency it does not need for its own job -- see that crate's README) or being
duplicated at every call site.

**The check.** `covariance::check_spd(cov, context)` / `check_spd_row_major(cov, n, context)`
mirror `spoore_cdm::GaussianState`'s exact bar: finite, then symmetric (`SYMMETRY_RTOL =
1e-9`, relative to magnitude -- the identical formula `spoore_cdm::state`'s own private
constant uses), then a Cholesky attempt (`cov.clone().cholesky().is_none()` fails it, same as
spoore's `check_positive_definite`). A failure is a typed `CovarianceHygieneError`
(`NotFinite`/`NotSymmetric`/`NotPositiveDefinite`/`DimensionMismatch`/`NotSquare`) and
increments the process-wide counter `covariance::spd_check_failures()` -- never a silent
repair. `covariance::tests::equivalence_*` proves the mirror is not looser or stricter than
spoore's own check: the same fixtures spoore's own test module uses (well-conditioned,
asymmetric, indefinite, singular, and the large-magnitude-round-off-vs-small-magnitude-real
symmetry-tolerance boundary) are fed through both `check_spd_row_major` and
`spoore_cdm::GaussianState::from_slices` directly, and the two decisions are asserted to
agree on every one.

**The eigenvalue-proxy measurement.** A successful check also returns
`CholeskyDiagnostics::min_cholesky_diag_sq` -- the smallest `L[i][i]²` from the Cholesky
factor `P = L Lᵀ` that the check already computed. Precisely: each Cholesky pivot is a
Rayleigh quotient of `P`, so `λ_min(P) <= L[i][i]² <= λ_max(P)` for every `i`, which makes
`min_cholesky_diag_sq` an **upper bound** on the true smallest eigenvalue (not a lower one),
forced toward zero exactly when `λ_min(P)` is (since the product of all the pivots is
`det(P)`). Cheap, always available once the check has run, and a genuine drift signal across
samples or runs -- but not a substitute for an actual eigenvalue computation where the exact
value matters. `av-kernel` logs the smallest value seen over a run; see that crate's README.

**Opt-in nearest-SPD projection.** `covariance::nearest_spd(cov, floor_ratio)` /
`nearest_spd_row_major` implement eigenvalue clipping (Higham 1988's nearest positive
semidefinite matrix in Frobenius norm, specialized to an already-symmetric input, with
eigenvalues floored to `floor_ratio * (largest eigenvalue)` rather than exactly zero, since
Cholesky needs strict positive-definiteness). **Off by default** -- see the function's own
doc comment for the algorithm's named limits (not the iterative/non-symmetric form of
Higham's algorithm; not guaranteed to preserve trace or any other physical quantity; not
re-validated against any golden) and for why "used only if the DRM declares it" is, today, a
plain boolean parameter threaded by callers rather than an actual `DrmOptions` proto field
(`proto/altavista/v1/system.proto`'s `DrmOptions` has no such field, and `proto/**` is
read-only to this task -- adding an additive `bool nearest_spd_projection` there, the same way
question 76 added `parent_frame_id`, is proposed as upstream/schema follow-up, not applied
here). Every application is counted separately (`nearest_spd_projections_applied()`) and
logged loudly by the caller that applies it.

## Testing

```bash
export PATH="/opt/homebrew/opt/rustup/bin:$PATH"
cargo test --workspace         # Rust: unit + integration tests
cargo clippy -p av-cdm --all-targets -- -D warnings
.venv/bin/python -m pytest -q  # Python: includes the GMAT leap-second cross-check
```

`crates/gmat-sys` currently fails `cargo clippy --workspace --all-targets -- -D warnings`
on pre-existing, unrelated lints in its own examples/tests; that crate is out of scope for
this work.

## Known limitations (not silent)

- The `spoore_v0::frame` mapping is total but produces placeholder `frame_id`s that are not
  themselves registered `FrameDefinition`s (see above).
- `pb::Measurement.entity_hint` (new in v1) is left empty by `spoore_v0::measurement_to_pb`:
  spoore carries no equivalent field.
- The pre-1972 and post-2017 extrapolation rules in `time.rs`, restated above.
